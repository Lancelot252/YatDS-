# 第二周教案：提示词工程

## 一、课程基本信息

- **课程名称**：YatOL 人机协作课程
- **授课主题**：提示词工程（Prompt Engineering）[^1]
- **建议课时**：2 学时（90 分钟）
- **适用对象**：具备基础编程能力的计算机相关专业学生
- **先修内容**：编码 Agent[^2] 的基本概念与常见形态
- **教学环境**：编码 Agent 已打开课程项目工作区，能够读取目录与文件，并在授权范围内创建、编辑文件
- **教学范围**：严格对应《总计划.md》第二周。本周以工作区文件任务为载体练习 Prompt[^3]，不提前系统讲授需求拆解、上下文工程、项目阅读方法、Agent 工作流、工具权限、测试驱动、代码审查或风险治理
- **内容边界**：课堂只讲四种文件格式的用途与 Prompt 写法概览；Markdown[^4] 和 JSON[^5] 的详细文件语法、完整文件示例及检查方法不纳入本教案的 90 分钟教学内容
- **参考依据**：OpenAI Codex 文档与用例、OpenAI Prompt Engineering、Claude Code 工作原理、Prompt Library 与 Common Workflows

[^1]: 提示词工程是改进 Prompt 表达的方法。
[^2]: 编码 Agent 是能读取项目并使用工具完成编码任务的 AI 助手。
[^3]: Prompt 是用户交给 Agent 的任务说明。
[^4]: Markdown 是用简单符号排版标题、列表和代码的文本格式。
[^5]: JSON 是用键值和数组保存结构化数据的文本格式。

课堂统一前提：已知目标路径时直接指定文件；路径尚不明确时，要求 Agent 先检查工作区并定位相关文件，再实施修改。学生无需手工复制整个项目内容。

## 二、教学目标

完成本课后，学生应能够：

1. 解释 Prompt 与 Prompt Engineering 的基本概念。
2. 说明 Prompt 如何影响编码 Agent 对工作区范围、目标文件、修改要求和交付形式的理解。
3. 识别并编写 Prompt 的背景、目标、输入、输出和约束。
4. 根据任务需要使用 Role Prompting[^6]、Few-shot Prompting[^7] 和 Step-by-step Prompting[^8]。
5. 指示编码 Agent 在指定路径创建或修改 Markdown、JSON、表格或代码文件。
6. 将模糊、冗余或冲突的 Prompt 改写为清楚、相关、具体的任务说明。
7. 比较 Prompt 修改前后的文件变更结果。

[^6]: Role Prompting 是给 Agent 设定任务角色。
[^7]: Few-shot Prompting 是用少量示例说明预期写法。
[^8]: Step-by-step Prompting 是把任务按顺序分成几个步骤。

## 三、教学重点与难点

### 教学重点

- Prompt 的五个基本组成部分。
- 三种常用提示方法的作用和适用场景。
- 四种输出格式及其主要用途（概览）。
- 高质量 Prompt 的设计与改进方法。

Markdown 和 JSON 的具体标记、数据类型、转义规则、完整文件结构与语法检查不列为本课教学重点。

### 教学难点

- 区分必要背景与无关信息。
- 把“写得更好”等抽象要求改成具体要求。
- 判断何时需要示例或分步说明，避免机械套用技巧。
- 在完整性与简洁性之间取得平衡。

## 四、教学准备

### 教师准备

1. 准备一个已打开示例项目工作区的编码 Agent，例如 Codex 或 Claude Code。
2. 准备同一任务的模糊版、改进版和结构化版 Prompt。
3. 在示例工作区中准备 README、JSON 数据、Markdown 表格和 Python 源文件。
4. 准备一份包含信息不足、信息过多、要求冲突和格式不清等问题的 Prompt。

### 学生准备

- 复习变量、函数、列表和基本时间复杂度。
- 能够阅读简单 Python 函数和输入输出样例。
- 能够在编码 Agent 中打开课程示例工作区，并查看文件变更。

## 五、核心知识一：Prompt Engineering 基础

### 1. Prompt 是什么

Prompt 是用户交给编码 Agent 的任务说明。编码 Agent 可以根据 Prompt 检查工作区、读取相关文件、创建或编辑文件，并在完成后报告改动与验证结果。

示例：

```text
完善这个项目。
```

```text
读取工作区中的 `src/stack.py` 和 `README.md`。
在 `src/stack.py` 中为 `Stack` 类补全 `push`、`pop` 和 `peek`；
保持现有公开接口，空栈调用 `pop` 或 `peek` 时抛出 `IndexError`；
同步更新 `README.md` 中的使用示例。完成后说明修改了哪些文件。
```

第二条 Prompt 指定了读取范围、目标文件、修改位置、行为要求、接口约束和交付说明，因此 Agent 可以直接在工作区中执行任务。

### 2. Prompt Engineering 是什么

Prompt Engineering 是围绕编码 Agent 任务说明进行设计、比较和改进的方法。它根据实际文件变更调整信息、结构和表达。

示例过程：

```text
初始 Prompt：把搜索功能补好。
观察结果：Agent 无法确定应修改哪个文件以及保留哪些接口。
改进 Prompt：读取 `src/search.py`，补全其中的 `linear_search`，未找到时返回 -1。
再次观察：目标文件和主要行为已经明确，但重复元素行为仍不清楚。
继续改进：保持现有函数签名，找到重复值时返回第一次出现的索引；只修改 `src/search.py`。
```

### 3. Prompt 在编码 Agent 中的作用

在编码场景中，Prompt 会影响 Agent 如何确定工作目录、读取哪些现有文件、修改哪些目标、保持哪些接口、执行哪些验证，以及完成后如何汇报。

示例：

```text
把链表实现完整。
```

这条 Prompt 没有说明目标文件、现有接口、允许的修改范围和完成标准。

```text
读取 `src/linked_list.py`，补全现有 `SinglyLinkedList` 类中的
`append`、`prepend`、`find` 和 `to_list`。保持类名与方法签名；
`find` 未找到时返回 -1；只修改该文件。完成后列出修改摘要。
```

第二条 Prompt 减少了 Agent 必须自行猜测的内容。

## 六、核心知识二：Prompt 的五个基本组成部分

### 1. 背景（Context）[^9]

[^9]: Context 是 Agent 完成任务需要知道的信息。

背景说明 Agent 当前面对的工作区环境，以及哪些已有条件会影响文件修改。常见背景包括项目语言、版本、目录位置、现有功能和约定。

示例：

```text
当前工作区是一个 Python 3.12 数据结构项目。
查找实现位于 `src/search.py`，公开接口已经被其他模块调用。
```

背景应与当前文件任务直接相关。无关的项目历史不会提高修改质量。

### 2. 目标（Goal）

目标说明 Agent 最终要对工作区完成什么操作。目标应使用明确动词，例如读取、定位、补全、修改、创建或更新。

示例：

```text
补全 `src/search.py` 中的 `linear_search`，返回 target 第一次出现的索引。
```

下面的目标过于模糊：

```text
把搜索功能弄好一点。
```

### 3. 输入（Input）

输入是 Agent 完成任务时可以读取的工作区材料，包括文件路径、目录、现有代码、配置、错误日志和样例数据。文件已经位于工作区时，Prompt 应优先给出路径，无需把整段内容粘贴到任务说明中。

示例：

```text
读取：`src/search.py`、`README.md`。
行为样例：`linear_search([3, 1, 3], 3)` 应返回 `0`。
```

给出准确路径和关键行为样例，可以减少 Agent 搜索范围与实现歧义。

### 4. 输出（Output）

输出说明 Agent 最终应把结果写到哪里，以及完成后需要汇报哪些信息。要求直接修改代码时，主要交付物是指定工作区文件的差异；要求解释或规划时，主要交付物可以是消息或文档。

示例：

```text
交付要求：
1. 在 `src/search.py` 中完成实现；
2. 在 `README.md` 中更新调用示例；
3. 不创建额外说明文件；
4. 完成后列出修改文件和各文件的主要变化。
```

如果不规定交付位置，Agent 可能只在消息中给出代码，也可能创建位置不合适的新文件。

### 5. 约束（Constraints）

约束规定必须遵守的边界，例如禁止使用某个函数、限制篇幅或保持函数签名。

示例：

```text
- 使用 Python 3.12；
- 不使用 list.index()；
- 保持函数签名为 linear_search(nums, target)；
- 只修改 `src/search.py` 和 `README.md`；
- 不重命名或移动文件。
```

约束必须具体且相互一致。“必须非常详细”与“只能写一句话”会产生冲突。

### 6. 五部分组合示例

```text
背景：当前工作区是 Python 3.12 数据结构入门项目，现有实现位于 `src/search.py`。

目标：读取并补全 `src/search.py` 中的 linear_search，返回 target 第一次出现的索引，未找到返回 -1。

输入：读取 `src/search.py`；nums 是整数列表，target 是整数；nums 可能为空，也可能包含重复值和负数。

输出：直接编辑 `src/search.py`；完成后汇报修改文件、行为变化和复杂度。

约束：保持现有函数签名；不使用 list.index() 或其他现成查找函数；只修改目标函数。
```

五部分无需每次都写成五个标题。目标文件、目标行为、输出位置、禁止事项和验收方式已经明确时，可以合并成短 Prompt；会改变结果的信息必须保留。

## 七、核心知识三：三种常用提示方法

### 1. Role Prompting

Role Prompting 通过设定与任务有关的角色，限定 Agent 检查文件和实施修改时采用的专业标准。

示例：

```text
你是一名维护教学示例代码的 Python 工程师。
读取 `src/queue.py`，补全缺失实现；保持代码适合初学者阅读，
保留现有接口和注释风格，只修改该文件。
```

角色应为任务提供真实信息。“你是世界上最强的程序员”没有说明接口、受众或质量标准，因此不能代替具体要求。

### 2. Few-shot Prompting

Few-shot Prompting 通过少量现有文件示例或输入输出样例，让 Agent 理解预期格式或分类边界。

示例：

```text
读取 `docs/complexity.md`，按现有行格式补充缺失条目。

示例：
数组按索引访问 -> 按索引访问：O(1)
单链表按值查找 -> 按值查找：O(n)

请补充：在可能退化的二叉搜索树中查找元素
```

示例应正确、相关并具有代表性。错误或过于单一的示例可能让 Agent 模仿错误模式。

### 3. Step-by-step Prompting

Step-by-step Prompting 将 Agent 的可观察操作按顺序排列，适合需要先检查现状、再编辑文件、最后核对结果的任务。

示例：

```text
请按以下顺序完成：
1. 读取 `src/stack.py` 和 `README.md`；
2. 确认 `Stack` 的现有公开接口；
3. 补全 `push`、`pop` 和 `peek`；
4. 更新 `README.md` 中的使用示例与复杂度表；
5. 检查最终改动是否保持接口一致，并汇报修改摘要。
```

这里的重点是规定可观察的工作顺序和交付结果，同时无需索要冗长的内部思考过程。

### 4. 三种方法的选择

| 任务 | 适合的方法 | 原因 |
| --- | --- | --- |
| 按教学代码规范补全示例文件 | Role | 需要限定维护标准与读者层次 |
| 按现有格式补充复杂度条目 | Few-shot | 文件中的示例能说明格式边界 |
| 先检查接口、再修改文件、最后汇报 | Step-by-step | 操作顺序与完整性重要 |
| 修改一个已明确文件、行文和替换内容的拼写错误 | 不需要额外方法 | 目标与结果已可直接检查 |

提示方法应按需使用，不应把 Role、Few-shot 和 Step-by-step 机械地塞进每条 Prompt。

## 八、核心知识四：输出格式控制

本部分在课堂中只作格式概览。教师应让学生知道：格式要求应同时说明目标文件、文件内部结构和完成后的汇报方式。Markdown 与 JSON 的详细语法、完整文件示例和检查清单不在课堂中展开。

| 输出格式 | 主要用途 | Prompt 中需要点明的内容 |
| --- | --- | --- |
| Markdown | README、项目说明、技术文档 | 标题层级、章节名称、是否包含列表或命令代码块 |
| JSON | 配置或机器读取的数据文件 | 文件路径、字段名、数据类型、允许值 |
| 表格 | 文档内的横向比较 | 目标文档、列名、比较对象、单元格标准 |
| 代码 | 项目实现文件 | 目标路径、语言版本、接口、依赖和修改范围 |

教师讲解时只需强调两点：

1. 先确定 Agent 要创建或修改的目标文件，再选择格式。
2. 只写格式名称不能确定交付物；还要补充目标路径、文件内部结构和允许修改的范围。

教师无需逐项讲解 Markdown 标记或 JSON 语法，也不安排相关课堂练习。

概览示例：

```text
项目说明写入 `README.md`；
机器读取的数据写入指定 JSON 文件；
比较结果写入目标 Markdown 文档中的表格；
功能实现直接写入指定源代码文件。
```

## 九、高质量 Prompt 的设计方法

### 1. 先写一个清楚目标

示例：

```text
补全二分查找功能。
```

这是可用起点，但还没有说明工作区路径、目标文件和修改范围。

### 2. 补充必要背景和输入

示例：

```text
当前工作区使用 Python 3.12。
读取 `src/search.py`；其中已有 `binary_search` 函数签名。
输入列表按升序排列，项目要求使用迭代实现。
```

### 3. 明确输出和约束

示例：

```text
补全 `src/search.py` 中的 `binary_search`，保持现有函数签名；
不要使用递归；不要修改其他函数；
同步更新 `README.md` 中的调用示例，完成后汇报修改文件。
```

### 4. 根据需要加入提示方法

示例：如果文件任务需要固定执行顺序，可以加入 Step-by-step：

```text
执行顺序为：读取目标文件、确认现有接口、修改实现、更新文档、检查改动、汇报结果。
```

如果目标文件、修改要求和完成标准已经清楚，就不必再加入无关角色或示例。

### 5. 检查相关性、具体性和一致性

发送前检查三点：

- 每条信息是否与当前任务有关？
- 抽象词是否已经改成具体要求？
- 不同要求之间是否冲突？

示例：

```text
重构整个项目，但只能修改 `src/search.py` 中的一个函数。
```

这条 Prompt 存在冲突。可以改为：

```text
只优化 `src/search.py` 中 `binary_search` 的可读性，保持行为与接口不变，不修改其他文件。
```

### 6. 比较修改前后的输出

| 版本 | Prompt | 预期差异 |
| --- | --- | --- |
| V1 | “把搜索功能补好” | 目标文件、接口和修改范围不明确 |
| V2 | “补全 `src/search.py` 中的 `linear_search`，未找到返回 -1” | 目标文件与主要行为明确 |
| V3 | 增加读取范围、交付位置、约束和边界样例 | 文件改动更集中、更容易检查 |

改进 Prompt 时应观察文件差异和任务完成情况，避免只凭文字表述判断质量。

## 十、常见 Prompt 问题与改进

| 问题 | 有问题的示例 | 改进示例 |
| --- | --- | --- |
| 目标模糊 | “优化一下链表” | “在 `src/linked_list.py` 中为现有类补全 `find` 方法” |
| 背景不足 | “修复搜索功能” | “读取 `src/search.py`，项目使用 Python 3.12” |
| 输入不清 | “处理这些数据” | “读取 `data/numbers.json`，字段定义见 `docs/schema.md`” |
| 输出不清 | “整理一下” | “将项目说明写入根目录 `README.md`，按指定标题组织” |
| 约束缺失 | “补全查找函数” | “保持现有签名，不使用 `list.index()`，只修改目标函数” |
| 信息过多 | 在 Prompt 中复制大量无关项目历史 | 只给出相关路径、行为和约束 |
| 要求冲突 | “重构整个项目，只改一个函数” | 缩小目标或扩大允许修改范围 |
| 示例错误 | Few-shot 示例给出错误文件格式 | 先校对示例，再交给 Agent 模仿 |
| 技巧滥用 | 所有任务都加入夸张角色和十个步骤 | 只使用对当前结果有帮助的方法 |
| 格式含糊 | “生成一份说明” | 指定目标路径、Markdown 标题和允许修改的文件 |

### 改进反馈示例

Agent 第一次修改没有处理重复元素时，不要只说：

```text
改得不对，再处理一次。
```

可以具体指出：

```text
检查刚才对 `src/search.py` 的修改。
当前实现没有正确处理重复元素：找到多个 target 时应返回第一次出现的索引。
只修正该行为，保持函数签名和其他已完成修改不变。
```

具体反馈能保留已经正确的部分，只修改发现的问题。

## 十一、课堂教学过程（90 分钟）

| 环节 | 时间 | 教师活动 | 学生活动 | 教学目的 |

```text
背景：当前工作区是 Python 3.12 数据结构入门项目。
目标：补全 `src/search.py` 中的 `linear_search`，返回 target 第一次出现的索引，未找到返回 -1。
输入：读取 `src/search.py`；nums 可能为空、包含重复值或负数，target 是整数。
输出：直接编辑目标文件；完成后汇报修改位置和行为变化。
约束：保持现有函数签名；不使用 list.index()；只修改目标函数。
```

演示让 Agent 读取并修改一个预先准备的示例文件，只比较任务理解、修改范围和交付格式，不提前系统展开测试驱动、工具执行方法或代码审查。

## 十二、课堂总结与板书

### 课堂总结

1. Prompt 是编码 Agent 本次工作的任务说明，Prompt Engineering 是设计和改进任务说明的方法。
2. 编码 Prompt 的五个基本部分是背景、目标、输入、输出和约束。
3. Role、Few-shot 和 Step-by-step 应按任务需要选择。
4. Markdown、JSON、表格和代码分别适合不同工作区文件与交付用途；本课掌握用途与 Prompt 写法即可。
5. 高质量 Prompt 应清楚、相关、具体、一致，并避免无关信息和冲突要求。
6. 改进时应指出具体偏差，保留已经正确的部分。

### 板书设计

```text
Prompt Engineering

五部分：
背景 | 目标 | 输入 | 输出 | 约束

三种方法：
Role | Few-shot | Step-by-step

四种格式：
Markdown | JSON | 表格 | 代码

质量检查：
清楚吗？相关吗？具体吗？一致吗？
```
