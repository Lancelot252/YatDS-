# YatOL人机协作课程先导课

## 课程简介

本课程以数据结构项目为载体，讲解如何向编码 Agent 表达任务、提供项目上下文、审查文件修改并用测试验证结果。第一周只建立编码 Agent、工具形态和人机责任的基本认识；Prompt、项目指令、Git、MCP、Skill 和多 Agent 协作分别在后续周次展开。

## 前言

教师先指出：会用自然语言提问，只说明交互入口容易理解，不代表任务描述、权限设置和结果验收已经完成。编码 Agent 可以读取项目、修改文件和运行命令，因此学生还要学习如何限定目标、提供证据、检查差异并承担最终判断责任。本课程把这些能力拆成十二周，避免只靠个人试错积累零散经验。

## 什么是AI人机协作

AI 人机协作是人负责目标、授权和验收，AI 系统在限定范围内帮助分析、生成、修改和验证。课堂不以“能否生成一个完整项目”作为成熟度标准，而以任务范围、工具使用记录、运行证据和人工审查是否完整作为判断依据。

AI 编程工具的发展可以按交互能力理解：先是光标附近的代码补全，再是对话式代码解释，随后出现多文件编辑，最后发展为能够搜索项目、调用终端和根据结果继续执行的编码 Agent。具体功能和发布时间属于各产品事实，授课时以官方文档为准。

编码 Agent 与普通代码生成的关键差别，不是宣传中的“自主”程度，而是它能否围绕一个任务形成可检查的工作循环：读取上下文、调用工具、观察结果、继续修正并汇报证据。不同产品是否支持多文件编辑、后台执行、Subagent 或 Skill，应分别查阅当前官方文档，不能把一个产品的功能推广为所有 Agent 的共同能力。


## LLM使用的分类

### 一、网页对话

网页或 App 对话是 LLM 的一种直接交互形态：用户在输入框中提交自然语言和附件，产品返回回答或调用其已开放的工具。

这类界面不要求用户安装本地开发环境。若任务只需要概念解释或讨论代码片段，可以使用网页对话；若任务要求读取真实仓库、编辑文件和运行测试，还要确认产品是否连接了相应工作区与工具。

在教学中可以强调，网页对话体现的是 LLM 最基础的交互形态：用户提出需求，模型生成结果。它适合普通用户快速体验 AI 能力，也是理解 LLM 工作方式的入门场景。

---

### 二、CLI 命令行交互

CLI 是 Command Line Interface 的缩写，即命令行界面。以 Claude Code 为例，用户可以在终端中直接与 LLM 交互，让模型帮助查看项目、修改文件、运行命令和管理代码工程。

CLI Agent 在终端中运行，并以当前工作目录、项目文件和命令结果作为上下文。需要直接搜索本地仓库、运行构建或分析测试失败时，可以使用这种形态；用户仍要审查命令、权限和文件差异。


---

### 三、API 接口调用

API 是 Application Programming Interface 的缩写，即应用程序接口。以 DeepSeek API 为例，开发者可以通过 HTTP 请求或 SDK 调用模型能力，把 LLM 接入自己的系统、网站、App 或业务平台中。

API 允许应用程序用结构化请求调用模型，并由开发者控制输入、工具、状态和输出处理。本课程不展开 API 应用开发，只说明它与用户直接操作的编码 Agent 界面不同。

---

### 四、编辑器内嵌

以 GitHub Copilot 为例，编辑器内嵌是指 LLM 被集成到 VS Code、JetBrains 等代码编辑器中，程序员可以在写代码的过程中直接获得模型帮助。早期的 Copilot 主要提供代码补全和智能建议，帮助开发者自动生成下一行代码或完整函数。

随着能力发展，编辑器内嵌的 LLM 已经不再只是补全代码，还可以解释代码、生成测试、修改已有代码，甚至根据自然语言需求进行跨文件编辑。这说明 LLM 正在从“代码提示工具”发展为“代码协作工具”。

编辑器内嵌让 AI 从外部问答工具变成开发环境的一部分，能够在程序员写代码的同时提供补全、解释、修改和重构建议。

---

### 五、独立应用

独立应用是以专门客户端承载模型、工作区和工具的产品形态。是否面向代码、能读取哪些文件、是否允许终端或后台任务，要按具体产品确认。

以 Claude Code Desktop、Codex 桌面端等编码 Agent 为例，用户可以选择本地项目，让 Agent 在授权范围内搜索仓库、修改文件并运行测试。是否支持远程环境、并行线程或 Pull Request，应按具体客户端和当前权限分别确认。

在教学中可以强调，独立应用可以围绕某一类专业任务形成完整工作流。例如，在代码工作中，AI 可以从需求理解、代码编写、测试修复到提交结果，逐步参与完整的软件开发过程。

---


## 为什么要学习AI人机协作

学习编码 Agent 的目的不是假定它必然提高效率，而是学会测量结果：任务是否符合需求、修改范围是否受控、验证是否通过、人工审查是否发现风险。只有这些证据成立，才能判断某次协作节省了时间或提高了质量。

计算机专业学生还需要理解编码 Agent 的能力边界：自然语言不能替代需求，生成代码不能替代运行，测试通过不能替代审查，工具权限也不能替代人的最终责任。

### 如何选择模型

模型选择应依据当前任务、可用工具、上下文长度、延迟、成本和本项目的实际评测。不要把“某模型擅长前端、某模型擅长后端”写成固定事实；同一模型在版本、提示、仓库和验证条件变化后，结果也会变化。

比较模型时固定同一任务、仓库基线、权限和验收标准，并记录完成时间、修改差异、测试结果和人工审查结论。

### prompt工程

Prompt 工程是指围绕大语言模型输入指令的设计、优化与评估方法。其核心目标是通过更加明确、结构化和可控制的提示词，引导模型在特定任务中生成更准确、更稳定、更符合需求的输出结果。与普通自然语言提问相比，Prompt 工程更强调任务目标、背景信息、角色设定、约束条件和输出格式的系统设计。

在编码 Agent 场景中，Prompt 要说明本次目标、相关输入、输出位置、修改约束和验收方式。写清这些信息可以减少 Agent 自行补齐关键决定的空间；最终质量仍以文件变化和运行证据判断。具体方法在第二周展开。

### 项目文件结构对LLM的影响

在使用大语言模型辅助编程时，项目文件结构会直接影响模型对代码库的理解效率和修改质量。LLM 在处理项目代码时，通常需要根据目录命名、文件职责、模块划分、配置文件、测试文件和文档说明来判断项目的整体架构。如果项目结构清晰，模型更容易定位相关代码、理解模块之间的关系，并生成符合原有工程风格的修改方案；如果项目结构混乱、命名不统一、缺少文档说明，模型就更容易出现找错文件、误解功能边界、重复实现或破坏原有逻辑等问题。

除了代码目录本身，面向 LLM 的说明文件也逐渐成为 AI 辅助开发中的重要技巧。例如，可以在项目根目录放置 AGENTS.md、CLAUDE.md、.github/copilot-instructions.md 等文件，用来说明项目背景、技术栈、代码规范、测试命令、提交要求和禁止事项。这类文件相当于给 AI Agent 准备的项目说明书，可以帮助模型在修改代码前了解项目约定，减少反复询问和错误尝试。


### 版本控制对LLM的影响

版本控制为人和 Agent 提供基线、文件差异和可追踪历史。清楚的提交边界有助于限定审查范围，但不能自动提高模型理解或代码质量。

`commit`、`branch` 和 `diff` 可以回答“相对哪个基线改了什么”。Agent 仍可能误读差异，因此必须由测试和人工审查验证。


### 什么是MCP服务器

MCP（Model Context Protocol，模型上下文协议）是一种用于连接大语言模型与外部系统的开放标准协议。在该协议中，MCP 服务器（MCP Server）是向模型提供工具、数据和上下文能力的独立服务组件，用于扩展模型的能力边界，使其能够访问本地文件、数据库、API 或外部应用系统。
MCP Server 可以被理解为“面向 AI 的插件服务”，它将外部世界封装成模型可理解的标准化接口，使大模型从单纯的文本生成器，转变为可以操作真实系统的智能体（Agent）。

### 什么是skill

Skill（技能）是面向 AI Agent 的一种可复用能力单元，用于将特定任务的“执行方法”进行结构化封装，使模型能够在不同场景中按需加载并执行标准化流程。与 Prompt 仅描述一次性任务不同，Skill 更强调“可复用的任务能力”，本质上是将一类问题的解决方法固化为模块化执行规范。

Skill 的核心价值在于将“经验型提示词”升级为“结构化执行流程”。例如，在代码生成场景中，一个 Skill 可以规定组件创建规范、文件放置位置、命名规则以及测试流程；在数据分析场景中，一个 Skill 可以定义数据清洗、统计方法选择以及可视化步骤；在文档生成场景中，则可以规定格式、结构与检查标准。
