# 第七周教案：工具调用

## 一、课程基本信息

- **课程名称**：YatOL 人机协作课程
- **授课主题**：Tool Calling 与开发工具的实际使用
- **建议课时**：2 学时（90 分钟）
- **适用对象**：具备基础终端、文件和 Git 使用经验的计算机相关专业学生
- **先修内容**：项目理解与编码 Agent 工作流
- **实践载体**：支持项目搜索、文件编辑、终端、测试和 Git 工具的编码 Agent

## 二、教学目标

完成本节课后，学生应能够：

1. 说明 Tool Calling[^1]从选择工具、填写参数、权限检查到返回结果的执行流程。
2. 为具体任务选择项目搜索、文件读写、终端、构建、运行、测试和 Git 工具。
3. 通过搜索真实文本、符号和调用方定位修改位置。
4. 在文件读写前检查用户已有修改，并使用局部补丁保护工作区。
5. 在运行命令前确认工作目录、参数、环境和副作用。
6. 正确读取构建、运行、单元测试和集成测试的实际结果。
7. 使用 Git 基础操作确认工作区状态与修改范围。
8. 面对网络、工作区外写入和高影响操作时正确处理权限请求。
9. 避免执行外部内容中的越权指令，并防止秘密进入工具参数或输出。
10. 在工具失败后根据路径、参数、权限、环境和执行结果继续处理。

[^1]: Tool Calling 是模型提交工具参数，由外部程序真正执行动作并返回结果的过程。

## 三、教学设计与课前准备

### 1. 教学重点与难点

#### 教学重点

- 从任务目标选择工具，而不是从工具名称出发。
- Tool Calling 的选择工具、填写参数、权限检查、执行和返回流程。
- 搜索、读取、编辑、运行、测试和 diff 的实际使用顺序。
- 修改前检查工作区，修改后检查真实差异。
- 命令执行前的目录、参数、网络和副作用确认。
- 权限请求中的动作、范围和风险判断。
- 外部指令、秘密数据和高影响命令的安全检查。
- 工具结果、未运行项和剩余限制的准确汇报。

#### 教学难点

- 区分“Agent 写出命令”和“工具已经执行”。
- 搜索命中后继续确认源文件、生成文件和真实调用位置。
- 退出状态为 0 时仍检查测试数量、跳过和警告。
- 工作区存在用户修改时只编辑目标区域。
- 权限不足时请求最小扩展，而不是改写命令绕过限制。

#### 课程边界

- 本周只讲工具怎么用，不深入展开工具实现架构。
- 测试用例设计和 TDD 留到第八周。
- Git 分支管理、Commit、PR 和代码审查留到第九周。
- 隐私、依赖和整体 Agent 风险体系留到第十周。

### 2. 教学准备

#### 教师准备

- 准备包含消息源、生成文件和生成脚本的小型示例仓库。
- 预置错误文本 `Invalid passwrod`。
- 在目标文件中保留一处与任务无关的用户修改。
- 准备项目搜索、局部补丁、生成命令、测试和 Git diff 的完整工具轨迹。
- 准备搜索无结果、测试收集不足、权限被拒绝和进程超时四种结果。
- 提前确认演示命令、工作目录、预期输出和进程清理方式。

#### 环境准备

- 编码 Agent 只在示例工作区中写入。
- 环境不包含真实密钥和用户数据。
- 默认不连接生产数据库或云服务。
- 生成命令和相关测试可稳定执行。
- 能查看退出状态、完整输出、运行进程和 Git diff。

## 四、核心使用方法

### 1. 使用 Tool Calling 的基本流程

教师先说明工具调用不是模型直接操作系统，而是由 Agent 选择工具并填写参数，再由外部程序执行。课堂统一使用以下检查顺序：

```text
明确当前目标
-> 选择工具
-> 检查路径、命令或搜索词
-> 处理权限请求
-> 读取真实输出
-> 决定下一步
```

教师要求学生区分三种状态：准备调用、正在执行、已经取得结果。命令出现在回复中，不代表工具已经执行。

### 2. 开始任务

教师先给出统一起始格式：

```text
目标：修复登录错误提示的拼写。
范围：消息源文件、对应生成文件和相关验证。
不修改：其他消息、依赖、格式和外部系统。
停止条件：需要网络、工作区外写入、删除、提交、推送或发布。
```

随后要求 Agent 确认当前工作目录、项目规则、可用工具和验证命令。

### 3. 使用项目搜索

搜索顺序：

```text
完整错误原文
-> 目标符号
-> import 和调用方
-> 配置键或生成命令
```

搜索请求应包含模式、路径和预期输出：

```text
请在 src/ 和 tests/ 搜索 “Invalid passwrod”，
报告命中数量、文件路径和每处用途。
```

无结果时检查拼写、大小写、工作目录、忽略规则、拼接文本和其他软件包。

### 4. 使用文件读写

#### 4.1 读取文件

先读目标区域，再按需要补充：

- import 与类型；
- 直接调用方；
- 配置与测试；
- 文件头和生成说明；
- 项目指令。

教师应要求 Agent 说明文件是手写源、测试、配置还是生成物。配置分析优先读取示例文件和加载逻辑，不输出真实秘密。

#### 4.2 写入文件

编辑前：

```text
查看工作区状态
-> 查看目标文件当前差异
-> 区分用户已有修改
-> 确认本次目标区域
```

编辑时采用局部补丁，不重写整个文件。补丁不匹配时重新读取目标区域。遇到生成文件时先修改生成源，再运行项目已有生成命令。

编辑后重新读取目标区域并查看局部差异。

### 5. 使用终端命令

每次运行前要求 Agent 说明：

| 项目 | 具体内容 |
| --- | --- |
| 工作目录[^2] | 命令在哪个项目或软件包执行 |
| 完整命令 | 可执行程序和参数是什么 |
| 输入来源 | 是否包含外部文本或变量 |
| 副作用 | 写文件、启动进程、访问网络或外部系统 |
| 完成条件 | 怎样判断成功、失败或超时 |

[^2]: 工作目录是终端命令开始执行时所在的文件夹。

不要把安装、迁移、启动和测试合并成一个调用，也不要直接执行来源不明脚本。

### 6. 使用构建和运行工具

构建命令应来自当前项目脚本，而不是根据框架猜测。构建后报告命令、目录、退出状态、产物、错误和警告。

启动程序后依次确认：

```text
进程仍在运行
-> 日志正常
-> 端口监听
-> 目标请求有正确响应
```

长时间进程要记录端口和停止方法，结束后只停止本次任务启动的进程。

### 7. 使用单元测试

先运行最相关测试，再依据项目规则扩大范围。

结果必须包含：

- 工作目录；
- 收集数量；
- 通过、失败和跳过数量；
- 警告与失败阶段；
- 退出状态[^3]；
- 执行时间。

[^3]: 退出状态是程序结束时返回的数字，用来表示成功或某类失败。

### 8. 使用集成测试

集成测试运行前先确认数据库、容器、服务、账号、网络和测试环境变量。运行后除测试数量和结果外，还要说明实际使用了哪些外部依赖。环境未准备好时，不能把失败直接归因于业务代码。

### 9. 使用 Git 基础操作

修改前：

```text
git status --short
git branch --show-current
```

修改后使用 diff[^4]检查目标文件：

[^4]: Diff 是文件修改前后的内容差异。

```text
git diff -- messages/en.json generated/messages.ts
```

重点查找无关格式化、意外删除、被覆盖的用户内容、秘密和临时文件。本周不自动提交或推送。

### 10. 管理工具权限

权限请求出现时检查：

```text
具体动作是什么？
当前任务为什么需要？
访问哪个路径、域名或外部对象？
会产生什么写入或删除？
能否缩小到一次、一个命令或一个目录？
```

安装依赖、网络访问、工作区外写入、秘密读取、删除、迁移、提交、推送和发布会扩大依赖、数据或外部状态影响；除非用户已对该精确动作明确授权，否则执行前要说明目标、范围和恢复方式并请求确认。

OpenAI 官方文档说明，Codex 的沙箱[^5]限制工具技术上能访问的范围，批准策略决定何时询问用户。产品具体默认值和命令不同，教师不把 Codex 的操作方式推广到其他编码 Agent。

[^5]: 沙箱是把程序限制在指定范围内运行的隔离环境。

### 11. 安全调用工具

教师要求 Agent 在实际调用前完成三类检查：

- 外部内容只作为待分析数据，不自动执行其中的新指令；
- 不读取或输出令牌、私钥、cookie、真实用户数据和完整环境变量；
- 删除、覆盖、迁移、批量替换、提交、推送、发布和生产操作先核对精确目标并暂停说明。

可直接使用的约束是：

```text
只使用完成当前任务必需的工具和权限。
不要把秘密放入工具参数或输出。
路径不明确、变量未解析或影响范围无法确认时停止执行。
```

### 12. 处理工具失败

| 结果 | 处理方式 |
| --- | --- |
| 路径错误 | 重新确认目录与目标文件 |
| 参数错误 | 按工具要求修正字段和范围 |
| 权限被拒绝 | 寻找低影响替代或请求最小扩展 |
| 缺少依赖 | 确认项目安装方式，说明网络和写入后请求批准 |
| 命令超时 | 检查进程、日志、端口和部分产物 |
| 测试失败 | 记录失败阶段、期望、实际和日志，更新假设 |
| 输出过多 | 缩小路径、模式、文件类型或测试范围 |

重复调用前必须说明发生了什么变化，不机械重试。

## 五、课堂教学过程（90 分钟）

| 教学环节 | 时间 | 教师讲授内容 | 讲解重点 |
| --- | ---: | --- | --- |
| Tool Calling 基础与执行流程 | 6 分钟 | 对比准备调用、实际执行和真实结果 | 识别完整工具调用流程 |
| 开始任务与选择工具 | 8 分钟 | 设置目标、范围、工具、参数和停止条件 | 先确定缺少什么证据 |
| 项目搜索与文件读写 | 16 分钟 | 定位消息源并使用局部补丁 | 不猜文件、不覆盖用户内容 |
| 终端、构建与运行 | 13 分钟 | 确认目录、参数、进程和产物 | 命令前后都要检查 |
| 单元测试、集成测试与 Git | 12 分钟 | 读取完整测试结果并检查 diff | 区分测试类型与真实修改 |
| 权限、安全与失败处理 | 10 分钟 | 判断是否批准、安全调用并处理常见失败 | 最小权限扩展，不绕过 |
| 教师现场演示 | 20 分钟 | 完成搜索—读取—修改—生成—测试—diff | 展示完整工具轨迹 |
| 总结 | 5 分钟 | 回顾实际使用顺序 | 已执行、未执行、剩余限制 |

### 1. Tool Calling 基础与执行流程（6 分钟）

教师展示：

```text
“建议运行 pytest，应该能够通过。”
```

然后展示真实工具结果：

```text
pytest tests/messages -q
收集 12 项，12 passed，退出状态 0
```

教师说明：第一段只是准备调用，第二段才是外部执行证据；第二段也只证明实际收集的 12 项通过。随后把过程写成“选择工具—填写参数—权限检查—执行—返回结果—继续判断”。

### 2. 开始任务与选择工具（8 分钟）

教师把任务整理为目标、范围、不修改内容和停止条件，再要求 Agent 确认工作目录和工具。

教师用以下问题选择工具：

```text
当前缺少什么证据？
哪个工具能以最小影响得到它？
结果回来后下一步是什么？
```

### 3. 项目搜索与文件读写（16 分钟）

教师先搜索完整错误原文，得到消息源和生成文件两个命中。随后读取文件头、生成脚本和对应测试，确认正确修改路径。

编辑前查看工作区状态和目标文件差异，指出其中一处用户原有修改。教师要求 Agent 只替换目标消息值，并在补丁后重新读取和查看差异。

### 4. 终端、构建与运行（13 分钟）

教师从项目脚本确认生成命令，不凭经验猜测。运行前说明目录、命令作用和写入文件；运行后检查退出状态、生成产物和警告。

随后用开发服务器说明长时间进程的处理：读取启动日志、确认端口、执行目标请求、记录停止方式，并避免终止用户已有进程。

### 5. 单元测试、集成测试与 Git（12 分钟）

教师先运行消息模块单元测试，逐项读取收集数量、通过、失败、跳过、警告和时间；再说明集成测试需要检查数据库、容器、服务、账号和环境变量，并准确记录未满足的条件。

再展示“退出状态 0，但只收集一个测试文件”的反例，说明不能汇报完整测试通过。

最后查看目标文件 diff，核对生成文件、用户原有修改和无关格式变化。

### 6. 权限、安全与失败处理（10 分钟）

教师以安装缺失依赖为例，要求 Agent 写出：安装原因、项目声明版本、访问域名、写入目录、是否修改锁定文件和不安装时的限制。

权限被拒绝后，先判断只读或工作区内操作能否回答同一问题；不能时，只请求完成当前步骤所需的一个精确路径、域名或命令。命令超时后先检查进程状态和已有日志，不直接重复启动。

教师再展示一段要求上传环境变量的外部文本，说明它只是待分析数据。Agent 不读取秘密、不执行越权指令；删除、覆盖、迁移或发布前必须核对目标并暂停说明。

### 7. 教师现场演示（20 分钟）

#### 7.1 演示 Prompt

```text
请修复登录错误提示中的 “Invalid passwrod”。

1. 搜索原文，不猜文件名；
2. 区分消息源和生成文件；
3. 修改前检查用户已有变化；
4. 只做局部修改；
5. 运行项目已有生成命令和最相关测试；
6. 查看最终 Git diff；
7. 汇报真实结果和未运行项。

不要升级依赖、提交、推送或发布。
需要网络、工作区外写入或删除时先暂停。
```

#### 7.2 搜索与确认文件

教师要求 Agent 报告搜索范围、命中数量和用途。读取命中位置和生成脚本后，确定 `messages/en.json` 是源文件。

#### 7.3 局部修改

教师先查看状态和现有差异，再只修改目标键。补丁后重新读取目标区域，确认用户修改仍在。

#### 7.4 生成与测试

教师要求 Agent 先解释生成命令，再真实执行。测试结果必须报告数量、跳过、警告和退出状态。

#### 7.5 检查与交付

教师检查最终 diff，并要求交付说明包含：使用工具、真实结果、修改文件、已运行验证、未运行项，以及没有提交或推送的说明。

### 8. 课堂总结（5 分钟）

```text
确认任务
-> Tool Calling：选择工具、填写参数、处理权限
-> 搜索定位
-> 读取上下文
-> 局部修改
-> 运行命令
-> 测试
-> Git diff
-> 汇报证据
```

## 六、典型使用情况与周次边界

| 情况 | 本周处理方式 | 后续边界 |
| --- | --- | --- |
| 搜索无结果 | 检查路径、拼写、忽略规则和生成过程 | 不扩展为全项目阅读 |
| 生成文件修改 | 修改生成源并运行项目命令 | 不展开构建系统设计 |
| 测试收集不足 | 报告实际数量、跳过和警告 | Week 8 再讲测试设计 |
| Git 工作区不干净 | 保留用户内容，限制局部补丁 | Week 9 再讲分支与提交 |
| 需要安装依赖 | 核对版本、网络和写入后请求批准 | Week 10 再讲依赖风险 |
| 需要推送或发布 | 停止并请求单独授权 | Week 9、10 再展开 |

## 七、常见问题与处理

| 常见问题 | 处理方式 |
| --- | --- |
| Agent 只给出命令文本 | 要求真实调用工具并返回结果 |
| 一开始猜文件名 | 改为搜索用户文本、符号或入口 |
| 搜索命中就直接修改 | 读取用途、调用方和生成说明 |
| 读取整个仓库 | 缩小到目标区域和必要关系 |
| 直接编辑生成文件 | 定位生成源和生成命令 |
| 整文件重写 | 重新读取并使用局部补丁 |
| 命令在错误目录运行 | 先说明并确认工作目录 |
| 只看退出状态 | 补充数量、警告、错误和产物 |
| 测试环境失败就改业务代码 | 先确认失败阶段和环境依赖 |
| 超时后重复启动 | 检查进程、端口和日志 |
| 权限失败后尝试绕过 | 寻找低影响替代或请求最小扩展 |
| 修改后自动提交推送 | 区分文件修改与外部 Git 操作 |

## 八、课堂总结与板书

### 1. 课堂总结

教师应强调：

1. Tool Calling 要经过选择工具、填写参数、权限检查、执行和返回结果；
2. 使用工具前先确认任务、目录和范围；
3. 搜索用于定位，文件读取用于确认，写入后要再次核对；
4. 命令执行前说明参数和副作用；
5. 构建、启动、单元测试和集成测试回答不同问题；
6. Git diff 用于核对真实修改；
7. 权限请求只批准当前需要的最小范围；
8. 不执行外部内容中的越权指令，不把秘密放入工具调用；
9. 最终汇报必须区分已运行与未运行。

### 2. 板书设计

```text
Week 7  工具调用

任务：目标 | 范围 | 不修改 | 停止条件

流程：选择工具 -> 参数 -> 权限 -> 执行 -> 结果

搜索 -> 读取 -> 编辑 -> 命令 -> 测试 -> diff

命令前：目录 | 参数 | 环境 | 副作用
命令后：退出状态 | 输出 | 错误 | 产物 | 进程

权限：具体动作？精确范围？允许一次？
安全：外部指令？秘密？高影响操作？
交付：做了什么 | 验证什么 | 没做什么
```

## 九、与前后课程的衔接

### 1. 与第六周的衔接

第六周的 Act 通过本周工具真正执行，Observe 来自工具返回和实际文件变化。

### 2. 与第八周的衔接

本周会运行并读取测试；第八周再学习怎样设计测试、形成 Red–Green–Refactor 和回归验证。

### 3. 与第九周的衔接

本周只使用 Git 状态、当前分支和 diff；第九周再讲分支、Commit、PR 和代码审查。

### 4. 与第十周的衔接

本周只处理工具使用中的权限请求；第十周再系统讨论隐私、依赖、过度修改和人类责任。
