# YatDS 讲义网页

本目录包含“YatDS 人机协作课程讲义”的静态网页阅读器。网页不使用前端框架，也不需要安装 npm 依赖；课程正文由上级目录中的 12 份 Markdown 讲义生成。

## 一、内容来源与生成关系

讲义 Markdown 是课程内容的唯一源文件：

```text
讲义/week1.md
讲义/week2.md
...
讲义/week12.md
        │
        │ node 网页/build-content.mjs
        ▼
网页/content.js
```

修改课程正文时应编辑 `讲义/weekN.md`，不要直接修改 `网页/content.js`。`content.js` 是生成文件，再次运行构建脚本时会被整体覆盖。

本地图片同样从 `讲义/` 目录读取。例如：

```markdown
![GitHub Copilot 界面](figs/github-copilot.png "GitHub Copilot 在 VS Code 中的界面")
```

构建时，脚本会把 `讲义/figs/github-copilot.png` 复制到 `网页/figs/github-copilot.png`，并在生成内容中保留相对路径。

本地图片的网页地址会自动附加由文件内容生成的 `?v=...` 版本标识；`index.html` 中的 `content.js` 地址也会在每次构建后更新版本标识。替换同名图片并重新运行构建脚本后，浏览器会请求新的地址，普通刷新即可显示新图片，无需强制刷新。

## 二、目录结构

```text
网页/
├── README.md           # 本说明文件
├── index.html          # 页面结构和静态资源入口
├── styles.css          # 桌面端、窄屏和移动端样式
├── app.js              # 路由、目录、搜索、翻页和交互逻辑
├── build-content.mjs   # Markdown 转换与内容生成脚本
├── content.js          # 自动生成的课程数据
└── figs/               # 构建时复制的本地讲义图片
```

各文件职责如下：

- `index.html` 提供顶部栏、章节目录、正文区域、页内目录、翻页栏和搜索对话框。
- `styles.css` 定义讲义排版、表格、图片、代码块、术语注释和响应式布局。
- `app.js` 读取 `window.LECTURE_DATA`，根据 URL 片段渲染总览或具体内容页。
- `build-content.mjs` 依次读取 `week1.md` 至 `week12.md`，转换为 HTML，并写入 `content.js`。
- `content.js` 包含章节标题、内容页 HTML、搜索文本和生成时间。

## 三、生成网页内容

建议以项目根目录为当前工作目录运行：

```bash
node 网页/build-content.mjs
```

也可以进入网页目录后运行：

```bash
cd 网页
node build-content.mjs
```

脚本成功时会输出生成文件位置、章节数量和内容页数量，例如：

```text
Generated .../网页/content.js
12 chapters, 175 content pages
```

构建脚本只依赖 Node.js 标准库。建议使用 Node.js 18 或更高版本。

## 四、本地预览

可以直接打开 `index.html` 阅读，但浏览器在 `file://` 模式下可能限制剪贴板等功能。维护和检查网页时，建议从项目根目录启动本地静态服务器：

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory 网页
```

然后访问：

```text
http://127.0.0.1:8000/
```

结束预览时，在运行服务器的终端中按 `Ctrl+C`。

如果 8000 端口已被占用，可以换用其他端口，例如：

```bash
python3 -m http.server 8080 --bind 127.0.0.1 --directory 网页
```

## 五、页面与路由规则

网页使用 URL 片段保存阅读位置，不需要后端路由。

```text
#overview                    讲义总览
#chapter=1&section=1         第一章第一个内容页
#chapter=11&section=3        第十一章第三个内容页
```

每份 `weekN.md` 对应一个章节。Markdown 中的二级标题 `##` 会被拆分为独立内容页，因此：

- 一级标题 `#` 用作周次与章节名称；
- 二级标题 `##` 决定左侧目录中的内容页；
- 三级及更深标题用于当前页面的内部结构，并显示在右侧页内目录中；
- 第一处 `##` 之前的正文不会进入生成页面，应把章节正文写在二级标题之下。

路由中的章节或内容页编号超出范围时，前端会自动限制到现有范围。

## 六、阅读功能

当前网页提供以下功能：

- 12 周讲义总览和章节直达入口；
- 可展开、收起的左侧章节目录；
- 当前内容页的右侧页内目录；
- 跨章节连续的上一节、下一节导航；
- 标题和正文全文搜索；
- 内容页阅读进度提示；
- 代码块复制按钮；
- 术语注释上标、解释和页内跳转；
- 网络图片与本地图片显示；
- 桌面端、窄屏和移动端响应式布局；
- 键盘操作和“跳到正文”辅助入口。

常用快捷键：

| 操作 | 快捷键 |
| --- | --- |
| 打开搜索 | macOS：`Command+K`；Windows/Linux：`Ctrl+K` |
| 关闭搜索 | `Esc` |
| 前往上一内容页 | `←` |
| 前往下一内容页 | `→` |

当光标位于输入框或文本区域中时，左右方向键不会触发翻页。

## 七、响应式布局

页面包含三个主要宽度状态：

- 大于 1120px：显示左侧章节目录、中央正文和右侧页内目录；
- 761px–1120px：隐藏右侧页内目录，保留左侧章节目录；
- 760px 及以下：左侧目录改为抽屉式菜单，并简化顶部搜索按钮和底部翻页信息。

修改样式时应至少检查一个完整桌面宽度和一个不超过 760px 的移动端宽度，重点观察表格横向溢出、图片尺寸、底部翻页栏遮挡和长标题换行。

## 八、Markdown 支持范围

`build-content.mjs` 使用项目内的轻量转换器，并不是完整的 Markdown 或 GFM 解析器。当前支持：

- `#` 至 `######` 标题；
- 普通段落；
- 有序列表和无序列表；
- Markdown 表格；
- 引用块；
- 围栏代码块和语言标记；
- 行内代码；
- 粗体、斜体和删除线；
- Markdown 链接；
- 本地图片和网络图片；
- `[^序号]` 形式的课程术语注释；
- 水平分隔线。

示例：

````markdown
## 二、编码 Agent 基础

编码 Agent[^1] 可以读取项目并调用开发工具。

### 1. 示例

```text
读取项目
→ 修改文件
→ 运行验证
```

![界面说明](figs/example.png "图片标题")

[^1]: 编码 Agent 是能够围绕开发目标连续使用工具的 AI 系统。
````

当前转换器的主要限制：

- 不支持在 Markdown 中直接插入原始 HTML，HTML 会被转义；
- 列表按单层连续条目处理，不适合复杂嵌套列表；
- 表格使用 `|` 分隔单元格，单元格正文中不应直接出现未处理的 `|`；
- 图片必须单独占一行；
- 本地图片路径不能包含空格，并且必须位于 `讲义/` 目录内部；
- 链接和图片 URL 不能包含未经编码的空格；
- 内容分页只识别代码块之外的二级标题 `##`。

## 九、图片编写规则

本地图片路径以 `讲义/` 为基准，而不是以 `网页/` 为基准。推荐统一放入 `讲义/figs/`：

```markdown
![能够说明画面内容的替代文字](figs/图片名称.png "简短图注")
```

图片说明应满足：

- 替代文字说明图片中真正可见的界面或关系；
- 图注简短指出图片主题；
- 网络图片后紧跟“图片来源”段落，并提供来源链接、访问日期和产品边界说明；
- 本地课程截图注明“课程环境截图”和日期；
- 不使用空的 `![]` 图片标记；
- 不在图片中暴露 API Key、密码、令牌或其他敏感信息。

网络图片不会下载到本地，浏览网页时仍需要访问原始图片服务器。若课程需要离线使用，应先取得合适授权，再把图片保存到 `讲义/figs/` 并改用相对路径。

## 十、术语注释

正文第一次出现专业术语时使用：

```markdown
API Key[^1] 不应写入公开代码仓库。

[^1]: API Key 是用于识别调用者并授权其访问服务的一串保密字符。
```

注释定义应与引用处位于同一个二级标题 `##` 内容页中。否则网页分页后，点击上标可能无法定位到解释。每个内容页中的注释标签应保持唯一，解释只写一句易懂的短句。

## 十一、修改后的验证

修改讲义或网页后，至少运行：

```bash
node 网页/build-content.mjs
node --check 网页/build-content.mjs
node --check 网页/content.js
```

随后通过本地服务器检查实际页面。建议确认：

- 总览能够显示 12 个章节；
- 修改过的二级标题能够出现在左侧目录；
- 页内标题能够出现在右侧目录；
- 上一节和下一节可以跨章节工作；
- 搜索可以找到新增正文；
- 本地图片返回成功并具有非零宽高；
- 网络图片没有失效；
- 表格不存在意外横向裁切；
- 术语上标能跳转到本页解释；
- 浏览器控制台没有与网页有关的错误。

## 十二、常见问题

### 1. 修改 Markdown 后网页没有变化

确认已经重新运行：

```bash
node 网页/build-content.mjs
```

然后普通刷新浏览器。构建脚本会更新 `content.js` 和本地图片的版本标识；如果仍显示旧内容，请确认当前打开的是正确项目中的 `网页/index.html`，以及服务器提供的是本次构建后的文件。

### 2. 新增内容没有出现在目录中

左侧内容页目录只读取二级标题。确认标题写成：

```markdown
## 三、标题
```

如果标题位于未闭合的代码块中，也不会被识别为内容页。

### 3. 本地图片无法显示

确认图片：

- 实际存在于 `讲义/` 目录内部；
- 路径相对于 `讲义/` 正确；
- 文件名和大小写完全一致；
- 路径中没有空格；
- 构建后已经复制到 `网页/` 中对应位置。

例如 `figs/example.png` 应同时对应：

```text
讲义/figs/example.png
网页/figs/example.png
```

### 4. 点击术语上标没有跳转

检查 `[^序号]` 引用和定义是否一致，并确认二者处于同一个 `##` 内容页。不要把本页注释统一放到章末的另一个内容页。

### 5. 代码复制按钮不可用

优先通过 `http://127.0.0.1:8000/` 访问网页。部分浏览器会限制 `file://` 页面使用剪贴板 API。

### 6. `content.js` 文件很大

这是正常现象。该文件包含全部 12 周讲义的 HTML 和搜索文本。不要手工拆分或格式化生成文件；内容修改应回到 `讲义/weekN.md`。

## 十三、静态部署

网页没有服务器端依赖，可以部署到任意静态文件服务。部署时应完整保留以下文件：

```text
index.html
styles.css
app.js
content.js
figs/
```

发布前应先重新生成 `content.js`，并确认 `figs/` 中包含所有本地图片。由于页面使用相对资源路径，可以部署在域名根目录或普通子目录中；服务器需要能够返回 `.js`、`.css`、`.png`、`.jpg`、`.webp` 和 `.svg` 等静态资源。

## 十四、维护原则

- 课程正文以 `讲义/weekN.md` 为准，生成文件不作为编辑入口；
- 修改讲义后必须同步生成 `网页/content.js`；
- 修改构建脚本后必须执行 JavaScript 语法检查；
- 新增格式前先确认轻量 Markdown 转换器是否支持；
- 保持网络资料来源、访问日期和产品边界说明；
- 保持键盘导航、替代文字和可见焦点等基本可访问性；
- 不在网页、截图、代码示例或生成数据中写入敏感信息。
